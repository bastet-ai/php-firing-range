# Notes: string handling - client bytes → C heap, session keys, serializer framing

[GLM] 2026-10-21T03:05:12Z - All refs php-src-83 unless marked 74.

## Multipart string extraction primitives (main/rfc1867.c 83)
- `php_ap_getword` rfc1867.c:455-485: quote-aware word scanner (handles " and ' incl. backslash-escaped quote). Length-safe; consumes consecutive `stop` chars after match. Feeds Content-Disposition pair splitting.
- `php_ap_getword_conf` rfc1867.c:531-550: skips leading space, dispatches quoted → `substring_conf(str, strlen(str), quote)`; unquoted → scan to next space → `substring_conf(str, len, 0)`. This is where `filename=` and `name=` values come from (rfc1867.c:805-818, 819-822 74-equiv).
- `substring_conf` rfc1867.c:527-543: `emalloc(len+1)`; loop writes ≤ len bytes + NUL - **bounds-safe in 83**; reads `start[i+1]` at i==len-1 → reads the terminator (in-bounds; unquoted path reads *strend which is delimiter/NUL - in-bounds).
- `php_ap_basename` rfc1867.c:552-569: last `\` or `/` ��� strips path for `filename` (RFC 7578 comment added in 83; 74 has the classic IE comment). Result is a POINTER INTO the original emalloc'd `filename` buffer, not a copy (see 74 rfc1867.c ~1030: `s = _basename(...)`... verify exact line below).
- 74-only wart: `next_line` no-LF/buffer-full path sets `self->buf_begin = ptr` where `ptr==NULL` (failed memchr) - php-src-74/main/rfc1867.c:343-353. Transient; healed by `fill_buffer` (memmove guarded by `bytes_in_buffer>0`, then `buf_begin = buffer`). memchr(NULL,'\n',0) is technically UB but n=0. 83 removed the assignment (comment "Let fill_buffer() handle the reset", 83 rfc1867.c:349-352). Behavior delta logged in notes-upload-progress-core.md.

## Filename → where it goes (83 rfc1867_post_handler)
- Content-Disposition filename → `filename` (getword_conf, rfc1867.c:819-822) → possibly multibyte-converted (zend_multibyte_encoding_converter, rfc1867.c:823-831) → **FILE_START event passes `&filename` (rfc1867.c:962) → progress stores `current_file["name"] = *data->filename` session.c:3156 - the RAW (post-getword, PRE-basename) value** - wait, verify: is the progress "name" the basename or the raw one? rfc1867.c does `s = _basename(...)` later for $_FILES (rfc1867.c ~1120). Progress gets `*data->filename` at FILE_START which happens BEFORE basename (event at line 957-963 vs basename at ~1120). **So progress session data contains the UN-basenamed client filename** (path components included, NUL-free since getword works on C strings; backslash-escapes decoded). Double-check exact lines when logging final.
- `field_name` = `data->name` = the `name=` form-field param (client-controlled, no path stripping) session.c:3155.

## $_SESSION key forging (the strongest primitive)
- session.c:3146-3150 (83): key = `rfc1867_prefix + <value of part named PHP_SESSION_UPLOAD_PROGRESS>` via smart_str_appendl - **binary-safe: arbitrary bytes incl. NUL, `|`, quotes, control chars, UTF-8**; no validation anywhere on key.s content. Key is used for: zend_hash_update (3081), zend_hash_del (3093), zend_symtable_find (3040). zend_symtable_find with a non-numeric prefix string stays a string lookup (prefix prevents pure-numeric keys - "upload_progress_" default).
- Default serializer is **"php"** (session.c:830 83 / session.c:799 74, php.ini-development:1440 also "php") - NOT php_serialize. php ENCODER (session.c:984-1005): appends raw key, then **rejects keys containing '|' → returns NULL → save_current_state writes EMPTY session (session wipe)** - session.c:503-520 (`else { s_write(..., ZSTR_EMPTY_ALLOC()) }`). ⇒ **Progress key containing `|` wipes the whole $_SESSION on every progress write** (victim DoS; attacker can do this to ANY session they can address via sid - with use_only_cookies=Off they can pick the sid). Both branches have the pipe rejection.
- php DECODER (session.c:1010-1056 83): scans `while (*q != '|')` under `q < endptr` bound - NUL-byte keys SURVIVE round-trip (binary-safe name extraction via zend_string_init(p, namelen)). Branch delta: 74 php_decode truncated-tail returns **SUCCESS silently** (74 session.c:981-983: `if (++q >= endptr) goto break_outer_loop;` without retval=FAILURE) vs 83 sets `retval = FAILURE` (83 session.c:1029-1032). 74 keeps the session alive with partially-decoded vars; 83 destroys it.
- php_serialize DECODER (session.c:883-903): whole-array unserialize into fresh $_SESSION - no key validation at all (arbitrary keys incl. NUL round-trip).

## PS(id) - session ID bytes from client
- Progress sid sources (no session_start() scrub `\r\n\t <>'"\` at session.c:1624-1629 which ONLY runs in php_session_start): POST part named session_name (session.c:3139-3141), COOKIE, GET (early_find_sid session.c:3019-3034). Set as PS(id) at session.c:3123-3124 via zend_string_init (binary-safe).
- Reaches: s_open/s_read/s_write (php_session_initialize session.c:408-502, flush session.c:1687), SID constant rebuild (php_session_reset_id session.c:1456+, `smart_str_appends(&var, ZSTR_VAL(PS(id)))` - **appends treats sid as C-string: embedded NUL truncates** - session.c:1473-1478), url_rewriter if trans_sid.
- Containment: files handler validates `php_session_valid_key` [A-Za-z0-9,-] (mod_files.c:168-172, warning at mod_files.c:169-171) in ps_files_open. **Any other save handler (redis/memcached DSOs, custom PHP handlers, mm) receives the raw bytes.** mm: ps_sd_new over-allocates `sizeof(ps_sd)+ZSTR_LEN(key)` slack but stores key as refcounted zend_string copy (mod_mm.c:110-145, 83) - no inline copy overflow.
