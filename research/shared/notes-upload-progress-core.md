PHP 8.3 installs the session callback globally at module startup (`src/php-src-83/ext/session/session.c:2902`) and the RFC1867 parser invokes START for every accepted multipart/form-data POST after boundary/setup (`src/php-src-83/main/rfc1867.c:739-766`). START allocates a zeroed request-heap `php_session_rfc1867_progress`, copies Content-Length, and stores it in session globals (`src/php-src-83/ext/session/session.c:3110-3118`). The same flow is at PHP 7.4 `src/php-src-74/main/rfc1867.c:776-783` and `src/php-src-74/ext/session/session.c:3181-3189`.

Activation beyond START requires (a) a non-empty ordinary form field whose exact name is `PHP_SESSION_UPLOAD_PROGRESS`, creating the session key `upload_progress_` + the exact byte string value (`src/php-src-83/ext/session/session.c:3136-3149`), (b) an SID, and (c) a subsequent accepted file part (`src/php-src-83/ext/session/session.c:3154-3164`). SID sources are: a multipart ordinary field exactly matching `session.name` (`src/php-src-83/ext/session/session.c:3139-3142`); otherwise, when the progress-name field is processed, Cookie then (only if `use_only_cookies=0`) GET (`src/php-src-83/ext/session/session.c:3019-3033`). Thus defaults still allow an unauthenticated request to choose a Cookie SID; moreover a multipart `PHPSESSID` form field is accepted directly regardless of default `use_only_cookies=1` because that direct branch does not consult the flag (`src/php-src-83/ext/session/session.c:3139-3142`).

The first file initializes the exported array and opens/reads the client-selected session; updates read existing session state, inspect a prior same-key array for `cancel_upload`, overwrite that key with the live progress array, serialize/write, and close (`src/php-src-83/ext/session/session.c:3036-3083,3163-3212`). FILE_DATA mutates cached zval pointers and may update (`src/php-src-83/ext/session/session.c:3215-3225`); FILE_END copies temp-name/error/done and may update (`src/php-src-83/ext/session/session.c:3228-3244`). Multipart END either removes the key by default or marks done when cleanup is disabled, then shuts down session globals and destroys request-local progress state (`src/php-src-83/ext/session/session.c:3247-3271`). RFC1867 emits END on all exits after START via `fileupload_done` (`src/php-src-83/main/rfc1867.c:1258-1264`).

Default exposure is identical in both branches: enabled=1, cleanup=1, prefix `upload_progress_`, name `PHP_SESSION_UPLOAD_PROGRESS`, freq `1%`, min_freq 1 second (`src/php-src-83/ext/session/session.c:849-859`; `src/php-src-74/ext/session/session.c:818-828`). Session defaults use cookies=1, only-cookies=1, strict-mode=0 (`src/php-src-83/ext/session/session.c:837-839`), so no pre-authenticated application session is required: a syntactically acceptable attacker-selected Cookie SID reaches the save-handler path.
